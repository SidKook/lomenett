# Lomenett firmware

For the V3.6/V3.7 boards. UI built on the v0.93 storage model.

## Layout

```
rp2354/lomenett/   RP2354 firmware (Arduino sketch)
ch32_supervisor/   CH32V003 power supervisor (ch32fun)
picorvd2/          notes on the probe firmware used to flash the CH32
prebuilt/
  lomenett.ino.uf2           RP firmware
  lomenett_ch32_power.bin    CH32 supervisor (1536 bytes)
  lomenett_ch32_power.elf    same, for gdb load
  picorvd_lomenett_gp17.uf2  picorvd with SWIO on GP17
lomenett_extension/  browser extension (see its README)
```

| File in `rp2354/lomenett/` | Purpose |
|------|---------|
| lomenett.ino | pins, CH32 handshake/power-off, wheel, battery, console, main loop |
| ui.h | screens, icon carousel, nav stack, animation |
| icons_user.h | 89 entry icons (generated by `sim/gen_icons.py`) |
| secure.h, vault.h | LittleFS + AES-128-CBC storage, entry parsing |
| se050.h | SE050 key binding and random numbers |
| msc.h | USB drive mode: edit, CSV import, backup/restore |
| backup.h, decrypt.h | backup file format, unlock animation |
| totp.h | 2FA codes and clock |
| splash.h, logo.h, flip.h | boot animation, rotation transitions |
| lomenett_logic.h | wheel decoder, five-press gesture, battery gauge, orientation (hardware-free, tested by `sim/`) |
| sim/ | host simulators and tests |

## RP <-> CH32 contract

The CH32 owns the select button and the power rails.

```
GP18 -> CH32 PC1   READY  (RP OUTPUT, starts LOW)
GP11 <- CH32 PA1   MIRROR (RP INPUT): button level + ack pulses
GP17 -- CH32 PD1   SWIO, only for flashing the CH32
```

1. **Boot (`bootHandshake()`)**: after panel init, raise READY once, wait up to 3 s for MIRROR high (ack: panel power on), wait for it to drop, set READY LOW. Never raise it twice (that means shutdown).
2. **Button (`selectHeld()`, `selectPressedEdge()`)**: MIRROR high = pressed; a press is a rising edge. Reset the edge tracker after the handshake.
3. **Power off (`powerOff()`)**, always in this order: display off (`0xAE`), charge pump off (`0x8D 0x10`), wait 100 ms, then READY high 30 ms / low 30 ms / high (two edges within 150 ms = cut power). Then loop: if the rail is bridged and can't drop, reboot on a new MIRROR rising edge. Cutting power with the charge pump running killed earlier panels.
4. **Reflash is safe**: a lone READY edge while on = "RP rebooted"; the CH32 acks and keeps power up.

CH32 on its own: five presses (each within 2 s) = power on; hold 8 s = forced off; sleeps when off (wake press counts as press 1); detects the RT_EN debug bridge and never drives it low.

## UI notes

- One carousel widget for every menu; 89 pictograms + A-Z/0-9 badges per entry; A-Z jump ring in lists. Add an icon by drawing ASCII art in `sim/gen_icons.py` and running it.
- ~67 fps: I2C at 400 kHz; wheel polled from a 5 kHz timer interrupt (single core: pausing core 1 for flash writes hung saves on arduino-pico 6.0.0); time-based easing (`approach()`), so long frames don't change motion speed.
- Screen rotates with the accelerometer.
- `rp2354/lomenett/sim/build.sh` renders every screen on the PC, checks overlap/clipping, and makes a contact sheet (ImageMagick).

## Build

RP: Generic RP2350, USB stack Adafruit TinyUSB, flash 2MB (Sketch 1MB, FS 1MB; the vault lives in FS). Libraries: Adafruit GFX, Adafruit SSD1306, AESLib, Crypto.

```
arduino-cli compile --fqbn 'rp2040:rp2040:generic_rp2350:usbstack=tinyusb,flash=2097152_1048576' rp2354/lomenett
```

CH32: needs ch32fun and riscv64-elf-gcc. Put the folder at `ch32fun/projects/lomenett_ch32_power/` and run `make lomenett_ch32_power.elf` (plain `make` tries minichlink, which doesn't work here).

Tests:
- `ch32_supervisor/sim`: `make && ./sim` (power sequence with both chips modelled)
- `rp2354/lomenett/sim`: `./build.sh` (vault + 2FA tests, UI render); `make && ./sim` (wheel, gesture, gauge, orientation)

## Flash the RP

Open the serial port at 1200 baud and close it (or hold BOOTSEL), then copy `lomenett.ino.uf2` to the drive.

## Flash the CH32

SWIO (PD1) goes to the RP's GP17, so the RP is the programmer:

1. Bridge RT_EN (keeps 3V3 up for the RP even with a blank CH32).
2. Flash `picorvd_lomenett_gp17.uf2` onto the RP.
3. ```
   riscv64-elf-gdb prebuilt/lomenett_ch32_power.elf
   (gdb) target extended-remote /dev/ttyACM0
   (gdb) load
   (gdb) monitor reset
   (gdb) quit
   ```
4. Flash `lomenett.ino.uf2` back onto the RP.

Gotchas:
- `compare-sections` reports MIS-MATCHED even when fine; verify with `dump binary memory chip.bin 0x0 1536` and `cmp` against the .bin.
- If gdb didn't connect (port moved), `dump` silently reads the .elf.
- A sleeping CH32 ignores SWIO. It stays awake while bridged, for 10 s after reset, or if the button was held at power-up.

## Known gaps

- No CH32 watchdog (if it locks up, unplug USB and battery).
- Sleep current not measured.
